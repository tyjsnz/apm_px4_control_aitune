# 05 · 中段制导与拦截点计算

> **一句话概括**：导引头还没"看见"目标的那一大段时间里，导弹靠**惯导 + 卫星定位 + 数据链**
> 把自己**导向"截获窗口"**；而"该往哪飞"这个问题的答案，来自一个看似简单的问题——
> **目标和我，最后在哪一点、哪一刻相遇？**（拦截点解算）
>
> 这个问题的答案**不是路径规划**，而是一个几何/代数解；两者常被混为一谈，本文第 4 节专门拆开讲。

本文分六节：**①阶段划分 → ②截获前靠什么 → ③拦截点怎么算 → ④路径规划 vs 拦截解算 →
⑤本程序的分段制导实现 → ⑥FAQ**。配套的可调参数见
[03 · 仿真参数详解](03_仿真参数详解.md)，界面元素见 [04 · 界面操作与结果解读](04_界面与操作解读.md)。

## 1. 一次交战的阶段划分

真实防空/空空导弹的一次典型拦截，按"**信息来源**"（而不是按发动机）划分为三个阶段：

```
 发射                          导引头截获                 目标
  │←────────── 中段 ──────────→│←──────── 末段 ────────→│
  │   惯导递推 + 数据链修正      │   导引头自主寻的         │
  │   飞向"截获窗口"(篮框)       │   PN / PP 等导引律       │
  ▼                             ▼                         ▼
  t=0                     t = t_acq                    t = t_go
  R ≈ 9.5 km              R ≈ 4 km(截获距离)            R → 0
```

| 阶段 | 占比(默认场景) | 导弹"看得见"目标吗 | 信息来源 | 典型导引律 | 本程序对应 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 发射/助推 | 极短 | 否 | — | 程序转弯 | 未建模(简化掉) |
| **中段** | 时间与距离的**大头** | **否** | 惯导 INS + GNSS + 数据链 | 程序飞行、指令修正、**飞向预测拦截点** | `mid_mode` = pip / straight |
| **截获(交接)** | 一个瞬间 | 开始能看见 | 导引头开机搜索 | ——（判据见 §2.4） | `_check_acquire()` |
| **末段** | 最后几秒 | 是 | 导引头自主测量 | **比例导引 PN / 纯跟踪 PP** | `guidance_command()` |

**为什么要分段**：

1. **导引头开机前不能用寻的制导** —— PN 需要测量视线转率 λ̇，PP 需要测量视线角 λ，
   导引头没截获就没有这两个量，**公式无输入、无从计算**。
2. **中段占绝大部分能量与时间**，若中段把导弹带到目标"很远的旁边"，末段再强的导引律
   也补不回来（过载有限、时间有限）。
3. **中段的唯一使命是"截获"**：把目标送进导引头的**距离门限 R_acq** 与**视场 FOV** 构成的
   "**截获窗口**"里。截获成功 = 交接成功，末段才有得打。

> 默认场景实测（本程序）：总飞行 10.9 s，其中 **中段 5.84 s（R 从 9.5 km 到 4.0 km）**，
> 末段仅 5 s 左右。启用分段制导后 PN 脱靶量 1.0 m，与不启用时的 0.2 m 同量级 ——
> 说明"先把目标送进篮框，再交给末段"这条工程路线是成立的。

## 2. 导引头"看不见"目标时，靠什么

### 2.1 三种信息源

| 信息源 | 测什么 | 误差特性 | 优点 | 缺点 |
| :--- | :--- | :--- | :--- | :--- |
| **惯性导航 INS** | 自身加速度、角速度，递推得到位置/速度/姿态 | **误差随时间发散**（位置误差 ≈ 一次项+二次项累积） | 全自主、不依赖外部、抗干扰 | 单独用不了太久，漂移累积 |
| **卫星定位 GNSS** | 绝对位置、速度（接收机解算） | **误差不随时间增长**（有界、慢变） | 长期精度好、成本低 | 更新率低(1~10 Hz)、易被干扰/欺骗、动态下有延迟 |
| **数据链（指令修正）** | 地面/平台雷达对**目标**的跟踪结果，上行发给导弹 | 取决于雷达测控精度与传输延迟 | **唯一能提供"目标现在在哪"的外部信息** | 依赖链路、可被干扰、有延迟与带宽限制 |

**组合导航 INS/GNSS** 解决"**我在哪**"，**数据链**解决"**目标在哪**"——
两者相减才是**相对距离 R 与视线方向 λ**，这正是中段导引律的全部输入。

误差随时间的定性关系：

```
  误差
   ↑        纯 INS(漂移发散)
   │           ╱
   │         ╱      INS/GNSS 组合(有界)
   │       ╱ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─
   │     ╱
   │   ╱  ← 数据链更新后被"拉回"一次(阶梯状收敛)
   │ ╱
   └──────────────────────────────→ 时间
```

### 2.2 中段要解决的其实是"截获概率"

设中段结束时**目标相对导弹的横向位置不确定度**为 `σ_lat`，截获窗口能覆盖的横向范围约为：

```
截获窗口横向宽度 ≈ 2 · R_acq · tan( FOV / 2 )   (视场锥在 R_acq 处的弦长)
```

只要 `σ_lat` 远小于窗口宽度，截获概率就高。于是中段的一切工程手段——
更好的惯导、更频繁的数据链、把导弹**导向预测拦截点而不是当前位置**——
本质都是在**压 σ_lat**、**把目标稳稳地放在视场锥中央**。

### 2.3 中段的三种典型导引方式

| 方式 | 做法 | 信息需求 | 本程序 |
| :--- | :--- | :--- | :--- |
| **程序飞行** | 按发射时装订的航向/弹道飞行，中途不修正 | 只需初始装订 | `mid_mode = straight`（`a_cmd = 0`） |
| **指令修正** | 地面算好修正量，周期性上行更新 | 数据链 + 目标跟踪 | 简化为下一行的离线解算 |
| **飞向预测拦截点** | 用目标运动状态外推相遇点，把导弹指向它 | 目标位置+速度（数据链给） | `mid_mode = pip` |

三者中，**"飞向预测拦截点"最省末段过载**：它在中段就把碰撞三角形（见 §3.1）提前解出来并
把弹轴转到碰撞方向上，末段一开机就几乎在碰撞航线上，PN 只需做小修正。

### 2.4 截获判据（本程序采用的简化模型）

```
截获成功  ⇔  R ≤ R_acq   且   | wrap( λ − ψ ) | ≤ FOV / 2
            └─距离够近─┘     └─目标落在视场锥内(相对弹轴)─┘
```

- `R_acq`：导引头**截获距离**（雷达/红外的探测距离门限），超过它开机也看不见；
- `FOV`：导引头**视场全角**，程序中按 ±FOV/2 相对**弹轴 ψ** 判断（本程序未建模导引头
  万向架，视场随弹体固定，属有意简化）；
- `wrap(·)`：把角度归一化到 (−180°, +180°]，避免 ±180° 跳变。

> **注意距离与视场是"与"的关系**：距离很近但目标在视场外，同样截获不了 —— 这正是
> §5 实验 4、5 要观察的现象，也是**前置角会占用视场**这一重要工程事实的来源。

## 3. 拦截点（PIP）怎么算

### 3.1 问题与碰撞三角形闭式解

> **已知**：目标当前位置 `P_t`、速度 `V_t`；导弹当前位置 `P_m`、速度大小 `V_m`（方向待定）。
> **求**：相遇时刻 `t` 与相遇点 `P`，使 `P_m + V_m·t·û = P_t + V_t·t`。

令 `ΔP = P_t − P_m`，两边取模（`û` 是待求的单位方向，模长为 1）：

```
| ΔP + V_t·t |  =  V_m · t
```

两边平方、展开，得到关于 `t` 的**一元二次方程**：

```
( |V_t|² − V_m² ) · t²  +  2·(ΔP·V_t) · t  +  |ΔP|²  =  0
   └──── a ────┘           └────── b ──────┘     └─ c ─┘
```

- **`V_m > V_t`（本程序默认 600 > 250）⇒ a < 0**，抛物线开口向下、`c = |ΔP|² > 0`
  ⇒ 两根**一正一负**，取**最小的正根** `t`（更早的相遇时刻）；
- 算出 `t` 后相遇点就是 `P = P_t + V_t·t`，导弹瞄准方向 `û = (P − P_m)/(V_m·t)`；
- **判别式 < 0 或没有正根 ⇒ 目标不可达**（比如目标同向更快地逃跑）——
  此时退化为"指向目标当前位置"。

它与 [01 · 比例导引法](01_比例导引法PN.md) §3.2 的**前置角公式**是同一件事的两种写法：

```
sin( φ ) = V_t · sin( q_t ) / V_m        φ = 前置角, q_t = 目标相对视线的方向角
```

即"**碰撞三角形**"：导弹速度矢量必须偏离视线一个前置角，才能在前方与目标相遇。

### 3.2 本程序的实现：迭代求解飞行时间（迭代 TOF）

目标会转弯，闭式解只对"常速直线"成立。程序采用**不动点迭代**，把转弯也考虑进去：

```
t₀ = R / V_m                                   # 初始猜测: 按当前距离直飞
重复 5 次:
    (ax, ay) = target.position_at( t )          # 目标外推 t 秒后的位置
                                              #   直线: p + v·t
                                              #   转弯: 恒角速度圆弧的解析解
    t = | (ax, ay) − P_m | / V_m                # 导弹飞到该点需要多久
返回 ( t, ax, ay )
```

代码位置：`guidance.py → predict_intercept()` 与 `Target.position_at()`。

- 当 `V_m > V_t` 时这是**压缩映射**，3~5 次即收敛；
- 目标匀速转弯时 `position_at()` 用圆弧积分 `∫V·(cos,sin)(θ₀+ωt)dt` 的解析解外推，
  因此**对机动目标也能给出合理的预测点**（闭式解做不到这一点）；
- 迭代结果同时给出 **TOF（飞行时间）**，用于画布上评估"还有多久相遇"。

### 3.3 ZEM：为什么"预测拦截点"等价于"把 ZEM 压到 0"

**ZEM（Zero Effort Miss，零 effort 脱靶量）**的定义：
*从当前时刻起，如果**不再施加任何控制**，最终会偏离目标多少。*

```
ZEM = r × v_rel / |v_rel|          (二维情形取叉积的模, 即"按当前相对速度直线外推的最近距离")
```

它是**预测式**指标，不需要真的飞过去：`ZEM = 0` ⇔ 当前状态已在碰撞航线上 ⇔ 拦截点解存在。
现代制导律（最优制导 OGL、增强型比例导引 APN）常直接写成：

```
a_cmd ≈ N · ZEM / TOF²                # 把"未来偏差"按剩余时间平方摊成当前过载
```

可见：**PN 的 `a = N·V_c·λ̇` 与 `a ∝ ZEM/TOF²` 是同一思想的两种度量** ——
前者用"视线还在转吗"，后者用"将来会差多远"。本程序的中段 PIP 导引，
本质上就是"**先把 ZEM 压到接近 0，再开机**"。

### 3.4 卡尔曼滤波：拦截点解算的"输入"从哪来

§3.1/3.2 假设 `P_t、V_t` 已知，实际上它们由**雷达测量 + 卡尔曼滤波**估计：

| 环节 | 内容 |
| :--- | :--- |
| 状态向量 | 常速模型 CV：`[x, y, vx, vy]`；匀转弯模型 CT：再加 `ω` |
| 预测步 | `x̂⁻ = f(x̂, dt)`（就是本程序 `position_at()` 干的事），协方差 `P⁻ = F·P·Fᵀ + Q` |
| 更新步 | 雷达量测（距离、方位、多普勒）`z`，卡尔曼增益 `K = P⁻Hᵀ(HP⁻Hᵀ+R)⁻¹`，`x̂ = x̂⁻ + K(z−Hx̂⁻)` |
| 输出 | **点估计 → 喂给 PIP 解算**；**协方差 → 决定截获概率**（不确定椭圆是否落在视场锥内） |

所以完整的链条是：

```
雷达量测 ──卡尔曼──→ 目标状态估计(含协方差)
                        │
                        ├──→ 迭代 TOF 解算 ──→ 拦截点 P + TOF ──→ 中段把弹轴指向它
                        │
                        └──→ 不确定度 σ_lat ──→ 与视场锥比较 ──→ 截获概率
```

> **四种做法一览**

| 方法 | 输出 | 是否考虑目标机动 | 本程序 |
| :--- | :--- | :--- | :--- |
| 碰撞三角形闭式解 | `(t, P)` 一个解析解 | 否（常速直线） | 文档讲解用 |
| **迭代 TOF** | `(t, P)`，可嵌入外推模型 | **是**（圆弧外推） | ✅ `predict_intercept()` |
| ZEM / 最优制导 | 直接过载指令 `a ∝ ZEM/TOF²` | 部分（模型内） | 未实现（扩展方向） |
| 卡尔曼滤波 + 模型预测 | 状态估计 + 协方差 → PIP + 截获概率 | 是 | 未实现（扩展方向） |

## 4. 路径规划 ≠ 拦截点解算 ≠ 轨迹整形

这三个词在中文资料里经常被混用，其实**回答的是三个不同问题**：

| 维度 | **路径规划** path planning | **拦截点解算** intercept geometry | **轨迹整形** trajectory shaping |
| :--- | :--- | :--- | :--- |
| 回答的问题 | *这条**路**怎么走？* | ***在哪、何时**相遇？* | *沿什么**形状**飞过去？* |
| 输入 | 静态/先验地图（地形、禁飞区、威胁） | 双方运动状态（位置、速度） | 已定的目标点 + 约束（落角、高度、能量） |
| 输出 | 一串**路径点/航路** | **一个点 P + 时刻 t** | 一条**被"掰弯"的弹道** |
| 时间维度 | 通常与"何时到达"解耦（或另做时间分配） | **核心就是时间**（TOF 必须解出来） | 强调过程（落角、高度剖面） |
| 是否避障 | ✅ 核心目标 | ❌ 不管障碍 | 可能（软约束/惩罚项） |
| 典型算法 | A*、Dijkstra、Voronoi、RRT、人工势场 | 碰撞三角形、迭代 TOF、ZEM 解 | 偏置比例导引、轨迹整形制导、最优控制 |
| 本程序对应 | **无**（战场是空的） | ✅ 中段 `pip` 模式 | 弱相关（PN 的"平行接近"本身就是自然生成的弹道形状） |

**三者的层级关系**（从上到下，越往下越"实时"）：

```
任务层   ┌──────── 路径规划 ────────┐   "从哪出发、走哪条航路(避开禁飞区)"
解算层   ┌──── 拦截点解算 (PIP) ────┐   "目标会在哪一点、哪一秒出现"
制导层   ┌── 导引律 PN / PP ──────┐     "当前偏差多大、要多少过载去修"
执行层   └── 舵机 / 一阶滞后 τ ──┘     "过载能不能真的打出来"
```

几个常见误区：

1. **"算出拦截点 = 规划好弹道"**：错。拦截点只是一个**几何解**，导弹能不能飞到那里，
   由制导层（过载限制、执行机构滞后、目标后来又转弯）决定 —— 所以 PIP 每一步都要**重算**，
   本程序中段每个仿真步都调用一次 `predict_intercept()`。
2. **"路径规划也能用在导弹上"**：可以，但场景不同 —— 只有存在**障碍/禁飞区/威胁区**
   （地形遮挡、敌方防空、禁射区）时才需要。本程序战场是空的，因此**没有路径规划**。
3. **"轨迹规划就是导引律"**：轨迹整形是**在导引律之上叠约束**（例如"必须以 60° 俯冲命中"
   的落角约束 → 偏置比例导引），底层仍然要靠过载执行，属于制导层的修饰。

## 5. 本程序的实现：分段制导（中段 → 末段）

### 5.1 界面控件（面板「导引头 / 分段制导」组）

| 控件 | 符号 | 范围 | 默认 | 含义 |
| :--- | :--- | :--- | :--- | :--- |
| 启用分段制导（复选框） | `phased` | 开/关 | **关** | 关闭时行为与旧版完全一致（开机即末段），保证原实验可复现 |
| 中段方式（下拉框） | `mid_mode` | pip / straight | **pip** | `pip` 指向预测拦截点；`straight` 程序直飞(`a_cmd=0`) |
| 截获距离 R_acq | `acq_range` | 500 ~ 15000 m | **4000 m** | `R ≤ R_acq` 才有机会截获 |
| 截获视场 FOV | `acq_fov` | 10 ~ 180 ° | **90 °** | **全角**；判据用 ±FOV/2 相对弹轴 |

> 关闭复选框时，其子控件自动置灰。修改任意参数都会**自动重置并暂停**（与其它参数一致）。

### 5.2 判据与切换逻辑（`guidance.py`）

```python
# Missile.step() 每个仿真步:
if p.phased and not self.acquired:
    self._check_acquire(r, los)              # R ≤ R_acq 且 |λ−ψ| ≤ FOV/2 → acquired=True
self.phase = "末段" if (not p.phased or self.acquired) else "中段"

if self.phase == "中段":
    cmd = self.midcourse_command(tgt)        # pip → 指向预测拦截点; straight → 0
else:
    cmd = self.guidance_command(r, los, los_dot, vc)   # 末段: PN / PP
self.a_cmd = clamp(cmd, -Gmax·g, +Gmax·g)    # 之后照常: 限幅 → 一阶滞后 → 积分
```

关键状态量（`Missile` 上）：

| 属性 | 含义 |
| :--- | :--- |
| `phase` | `"中段"` / `"末段"` |
| `acquired` | 是否已截获（不分段时恒为 True） |
| `acq_t` / `acq_r` / `acq_pos` | 截获时刻、截获瞬间的 R、截获点坐标 |
| `trail_split` | 弹道分段下标：`trail[:split]` 是中段，`trail[split:]` 是末段 |

### 5.3 画布上的可视化（`canvas.py`）

| 元素 | 样式 | 何时出现 |
| :--- | :--- | :--- |
| **中段弹道** | 暗色**虚线** | 分段开启且已跨过截获点 |
| **末段弹道** | 亮色实线（发光） | 截获之后（不分段时全程如此） |
| **视场锥 FOV** | 弹体前方淡色三角 + 点线边 | 未截获时；尖端标 `FOV 90°` |

## 6. 常见问题 FAQ

**Q1：为什么中段不直接用比例导引？**
PN 的输入是**视线转率 λ̇**，这个量只有导引头截获目标后才测得到。中段"看不见"，
公式没有输入。中段只能依赖**自身惯导 + 外部给的目标状态**（即 §2 的三种信息源）。

**Q2：为什么不默认打开分段制导？**
保持默认关闭，是为了让原有 9 组数值实验、GUI 测试的基线**完全不变**（可回归对比；
现在 `selftest.py` 扩充到 12 组，其中后 3 组专门测分段制导）。
需要演示中段/截获现象时，勾上即可 —— 默认参数（pip、4 km、90°）下默认场景约 5.8 s 就截获，
结果与关闭时基本一致（脱靶 1.0 m vs 0.2 m）。

**Q3：截获后会不会又丢失目标（失锁）？**
本程序简化为**一次截获即保持**（真实导引头有跟踪视场限制、目标闪烁、干扰下的失锁与
重截获）。想模拟失锁，可在 `_check_acquire()` 的反面加"跟踪丢失"判据 —— 属于扩展方向。

**Q4：FOV 是半角还是全角？视场锥怎么画的？**
控件给的是**全角**，判据与画布锥都按 **±FOV/2** 使用。FOV=90° 即 ±45°。

**Q5：为什么"FOV 15° 尾追"会显示"命中却未截获"？**
因为**碰撞航线本身要求一个前置角**（见 §3.1）。尾追交会时需要的前置角约 17°，
导弹机头朝的是"相遇点"而不是"目标现在的位置"，于是 `|λ − ψ| ≈ 17°` **始终大于 7.5°**
（15° 的一半），导引头从头到尾看不见 —— 但中段的 PIP 解算足够准，弹道直接擦过目标。
这**不是 bug**，恰恰说明：**窄视场必须配搜索/扫掠能力（或更宽的万向架）**，
真实系统给导引头加扫描模式正是为了解决这个问题。

**Q6：中段为什么不能"一直飞向目标当前位置"（纯跟踪式）？**
可以（相当于把目标当前位置当拦截点），但那是**零前置角**方案：末段开机时速度方向
不带提前量，末端过载需求反而更大（参见 [02 · 纯跟踪法](02_纯跟踪法PP.md) §3 的末端发散）。
指向**预测拦截点**能在中段就把前置角建立好，末段最省过载。

**Q7：拦截点算出来是固定的吗？**
不是。它**每一步都要重算**：目标在动、还会转弯，且 §3.4 的卡尔曼估计也在不断更新。
本程序在中段的**每个仿真步**都调用一次 `predict_intercept()`，相当于"连续重解算 + 连续修正"。

**Q8：拦截点解算和路径规划到底差在哪？**
一句话：**拦截点解算是"解一个方程"，路径规划是"搜一条路"**。前者输出一个点和一个时刻，
不需要地图、不避障、必须解出时间；后者输出一串航路点，依赖环境信息，通常不在乎"何时到达"。
详细对比见本文 §4 的表格。

**Q9：想继续扩展，可以加什么？**
- **数据链延迟与更新率**：把目标状态改成"保持上一次更新值"，看截获概率如何随延迟下降；
- **卡尔曼滤波 + 噪声**：给量测加噪声，用 CV/CT 模型估计，再喂给 PIP 解算；
- **导引头万向架与扫描模式**：视场相对弹体可偏转/扫掠，解决 §6 Q5 的窄视场问题；
- **ZEM / 最优制导**：直接用 `a = N·ZEM/TOF²` 替代中段指令；
- **失锁重截获**、**发射离轴角装订**、**中段耗燃/能量管理**。
